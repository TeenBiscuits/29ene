# Domain docs

This repo uses a single-context layout:

- `GLOSSARY.md` at the repo root defines domain vocabulary.
- `docs/adr/` holds architecture decision records.

## Before exploring

Read GLOSSARY.md and ADRs relevant to the area being changed.
If they do not exist, proceed silently.
Domain-modeling creates them when terms or decisions are resolved.

## Use domain vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
If a needed concept is missing, check whether an existing term fits.
Record real vocabulary gaps for domain-modeling.

## Respect decisions

If a proposal contradicts an ADR, identify the ADR and explain why
the decision should be reconsidered.
